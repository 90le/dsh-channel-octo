# IM Connect parity audit — Octo on DSH (source baseline)

**Decision: partial parity.** The Octo working tree has the core of a native DSH account and conversation experience and a narrow Octo text bridge. It does not establish IM Connect parity. The first hard compatibility gap is App Bot identity verification: the plugin accepts App Bot token syntax, but its required verify call only queries the User Bot table in the pinned server. The first release gates are route and Space isolation, credential handling, and ownership of DSH turns that can use tools or send output. Files, interactive cards, native streaming and broader sends each have distinct server and client contracts; passing a text round trip would establish none of them.

## 0.6.0 integration update

The remainder of this document is a source audit and acceptance plan, captured while the integration was underway. The release integrates declared deliverables, native attachments, bounded display and choice cards, authenticated one-use callbacks, live progress, and same-user WebSocket steering for Octo-owned DMs. Tool-enabled turns never borrow a Web-owned writer. The exact-host fixture, deployment health and real Octo client acceptance are separate evidence; see the README for the current supported surfaces.

## Blocking decisions and security constraints

1. **P0 — Identity and Space.** Decide whether release scope is User Bot only. The Local `identify` requires a non-empty UID and Space, and an App Bot token cannot take the ordinary pinned `verify-bot` path. Server's internal `/v1/internal/auth/resolve` has a different principal/OBO contract. Pin both API authority and authorized WS authorities; Local checks WS scheme/format (and allows loopback `ws:`), but the inspected registration path does not pin the returned `wss:` origin. Set a bounded policy for separate IM hosts. Prove two Spaces with identical local group/thread names, absent/conflicting payload Space, removed or blocked actors, and revoked tokens. In tool-enabled allowlist DM mode the worker does not run the friendship probe by default; an allowlist is not proof of current Octo access. In explicit group allowlist mode, a missing payload Space can pass the initial predicate; do not generalize that path to cross-Space routing without authoritative scope checks.
2. **P0 — DSH capability ownership.** `DshHost.applyPermission` calls `permissionPresets.set(agent.session, ...)` even on a borrowed Web session. The exact tag persists preset/sandbox/approval state; the borrowed cleanup only covers scoped controls, so this setting is not automatically reverted. Shared turn detection at completion cannot undo a tool that has already executed or a prompt that already crossed a route boundary. Establish origin-based per-turn ownership before any effects, or restrict first acceptance to text-only, channel-owned turns. A registered workspace, an allowlisted sender, a preset with no tools, and a host tool restriction are separate controls. A shared DSH process is not tenant or OS isolation. Check exact profile injection, Web approval behavior, custom preset startup, queued races, interrupts and stale handles; do not enable remote host commands or adopt ordinary sessions by copying IM behavior.
3. **P0 — Management and credentials.** The exact DSH tag uses Host/Origin and an authenticated Peer in `rpc-host.ts`; plug-in route existence does not make it an operator ACL. Verify actual profile composition and browser login. Local `credentialRequest` accepts forwarded HTTPS from loopback, same socket IP or configured proxy addresses; verify proxy strips inbound forwarded values, listener cannot be directly spoofed, and direct LAN HTTP and hostile Origin/Host are rejected. No credential or response body should appear in errors, history, telemetry or browser storage. Credential service and SQLite state need effective Windows ACLs and reparse-point checks; POSIX modes or absence from account JSON do not prove confidentiality. Verify interrupted rotate/remove and re-add, orphaned credential refs, and account lease across multiple profiles/processes. A local removal is not server token revocation.

4. **P0 for attachments — authority over bytes.** Require source-message and recipient authorization, HTTPS allowlisted storage origins, DNS/IP and redirect checks per hop (including rebinding and private-address cases), no cross-origin Bearer/Cookie forwarding, byte/time/count/image-decode bounds and temp cleanup. Reject traversal, symlinks/junctions, alternate data streams, device paths and replaced files. Recheck authorized roots when reading open handles. Explicit DSH delivery is necessary; extension checks, secret-name filters or private-key marker filters cannot detect arbitrary sensitive content. Separate “bytes uploaded” from “file message confirmed”; never log or post a presigned PUT URL.
5. **P0 for callbacks — ownership and ACK.** Latest WS mode demultiplexes matched actions; HTTP mode still ACKs unrecognized non-card events on its dedicated queue. Do not run another adapter on that Bot. A one-use claim plus local job protects execution; it does not atomically bind a server-created card or ACK with SQLite. Test create-before-bind crash, crash after local claim before ACK (including a last open card), stale/forged event, missed publication below the cursor, and unowned-event retention. Bind to exact revision/action, re-authorize before effects and keep host approval out of the initial callback scope.
6. **P1 — Reliable send and recovery.** Persist correlation and route before ACK; recheck revocable authorization immediately before generate and publish. Distinguish definite rejection (bounded 429 retry), accepted delivery, and ambiguous send/edit. Reconnect is not backfill; the server allocator/cursor caveat needs an explicit late-publication/replay-window acceptance test. Add route fairness and retention. Store per-effect receipts or an honest partial-delivery state; a final text message ID cannot stand in for file/card success.
7. **P1 — Scope and diagnostics.** Report identity, registration/CONNACK or poll, policy/capability probe, delivery receipt and client result separately. A healthy setting badge, verify HTTP 200, card profile 200 or presign URL is insufficient. Read the pinned policy and negotiate at runtime; explicit unsupported/unknown states are valid. Preserve IM Connect behavior in the same host without sharing stores, tokens or session bindings.
