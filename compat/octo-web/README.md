# Octo 客户端历史同步补丁

针对官方 [octo-web `7ace0e96`](https://github.com/Mininglamp-OSS/octo-web/tree/7ace0e96df36a2c03657178564c182fc23af6e25) 的独立审阅材料。**尚未合入、部署到正式 Octo，也未执行完整客户端 CI。** 此目录不随 DSH 插件安装包部署。

## 已复现的问题

文件消息已显示后，客户端发起历史同步。等待响应期间收到完整说明文字，随后旧历史快照覆盖实时列表，文字从列表消失；重新读取新历史后恢复。服务器正文并没有丢失。此源码复现与用户症状相符，但尚不能证明原现场使用了该版本或发生了同一请求时序。

[补丁](history-sync.patch) 为请求期间的新增消息建立临时记录，合并最新页而不拼回全部旧历史；重叠请求、历史定位、清空/卸载及旧分页回调按请求版本处理。去重优先采用服务端身份，保留删除/撤回状态；客户端消息号冲突不再误合并不同消息。仅改动 `Conversation/vm.ts`，新增 `historySnapshot.ts` 和对应测试。

- 补丁包含 26 个单测，隔离 Vitest 4.1.5 全通过；新增辅助模块 TypeScript strict 检查通过。
- 在另一份干净源码副本中检查并应用补丁，三份文件与已测副本逐字节一致；原始官方克隆保持干净。机器记录见 [verification.json](verification.json)。

消息列表夹具直接编译实际 ConversationVM、MessageWrap 和转换代码，并使用真实 SDK 消息对象；登录、服务、身份缓存和部分 UI/滚动依赖替换为测试实现。全部数据为合成内容，无生产 HTTP/WS。未覆盖真实浏览器像素位置、完整 monorepo 类型检查、全量 CI、编辑/流式更新的全部行为或长期撤回缓存。
