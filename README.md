# DSH Channel Octo

在 DeepSeek Harness Web 中并列加载的 Octo IM 插件。使用宿主模型和原生会话，支持私聊、群聊和子区的文字、文件与媒体附件，以及展示卡、确认卡和动态回复进度。可选本地白名单或 Octo 好友与成员准入。见[基础方案](PLAN.md)与[完整能力及验收计划](OCTO-COVERAGE.md)。

## 本地检查

要求 Node.js 24 或 26。运行时使用 `ws` 连接 Octo，用 `mdast-util-from-markdown` 保留 Markdown 段落及识别正文提及。

```sh
npm ci
npm test
npm pack --dry-run
```

## 隔离试用

以 DSH `0.2.1-rc.5` 为初始兼容目标。在临时 `DSH_HOME` 的 `web` profile 中，从已验证的工作树 `npm pack`，再执行：

```sh
dsh plugin --profile web add /absolute/path/dsh-channel-octo-0.17.0.tgz
```

包安装后默认关闭 Octo 收发。若使用专用测试 Bot，给 DSH 进程注入 `DSH_OCTO_BOT_TOKEN`，在测试 profile 的 `cordis.patch.yml` 中追加以下覆盖。确保工作目录已存在，状态目录仅服务账号可读写（Linux 上模式 0700）。使用实际 Octo API 前缀，例如以 `/api` 结尾的 HTTPS 地址；Bot 和 Space 必须与校验接口返回值一致。

```yaml
- id: dsh-channel-octo
  config:
    enabled: true
    apiBase: https://octo.example.invalid/api
    botUid: TEST_BOT_UID
    spaceId: TEST_SPACE_ID
    allowedUids: [TEST_USER_UID]
    allowedGroupIds: []
    allowedThreadIds: []
    threadRuleMode: thread-only
    cwd: /absolute/test-workspace
    stateDir: /absolute/private-octo-state
    waitSeconds: 15
    timeoutMs: 120000
```

默认仍采用本地用户和频道白名单，群与子区要求明确 @。群聊与子区只接受 User Bot（`bf_`）。显式配置子区时填完整通道 ID：32 位十六进制父群 ID、四个下划线、15–20 位数字短 ID；群 ID 不会自动放行旗下子区。升级前停止消费者并备份状态目录；私聊、群聊和默认子区模式沿用旧会话。

要让 Octo 好友及群友无需逐个配置 UID，在同一配置中设置：

```yaml
    senderPolicy: octo
    channelPolicy: joined
    mentionPolicy: octo
```

- `senderPolicy: octo`：删除或清空 `allowedUids`。私聊由 Octo 检查好友关系（User Bot 的所有者也可直接私聊）；群与子区检查父群成员身份。只需要取消逐人白名单时，可以继续用 `channelPolicy: allowlist` 控制开放哪些群或子区。
- `channelPolicy: joined`：删除或清空 `allowedGroupIds` 和 `allowedThreadIds`。接收 Bot 在绑定 Space 已加入的普通群及 Octo 实际投递到 Bot 的子区。
- `mentionPolicy: octo`：自动用 WebSocket 接收消息。明确 @ 仍有效；免 @ 仅在 Octo 返回父群有效开关为开、发送者是已确认的普通成员、且消息未 @ 其他人时触发。只想开放给好友和群友但保留必需 @，可省略此项。

WebSocket 注册占用该 Bot 的连接，同一 Bot 只运行一个消费者。旧模式仍可使用 `transport: events`；如需在必需 @ 模式使用实时接收，可设置 `transport: websocket`。短时断线会重连，已登记频道会按持久起点有界补读；从未登记的频道和服务端历史保留范围外的消息不保证恢复。

主区每轮读群规则。默认子区仅加载本区规则；设置 `threadRuleMode: inherit-group` 后，该插件允许的子区先读本区规则，再读父群规则，有冲突时以子区为准。父群继承会使用独立的子区会话，切回默认模式不会携带继承模式的历史。详见[群规则边界](OCTO-COVERAGE.md#群主区与子区规则)。

需要为测试 profile 设置可用的 DSH 模型。使用独立 Bot，不与其他连接程序同时消费其事件；启用后会确认该 Bot 收到的事件，超出当前支持范围的事件不进入模型。暂停时将 `enabled` 改回 `false` 并按环境流程重载 Web；本地状态和会话保留。

成功确认发送后，本地队列表只保留去重及投递记录，原生 DSH 会话仍保存对话。异常时查看服务中的 `dsh-channel-octo` 日志和状态库 `jobs` 的 `state`、`issue` 字段。对于 `review`，先在 Octo 查实际送达情况；插件不会自动重放不确定的任务或回复。

## 0.17.0

新增 App Bot 私聊接入：账号面板按令牌类型选择官方身份接口，可添加、编辑、停用、删除及更换同身份令牌。App Bot 使用 WebSocket 收消息、事件队列接交互卡回调；保留工作区、模型、预设、权限和工具范围配置。服务端管理应用的私聊范围，不要求填写虚构的 Space。

App Bot 支持当前私聊的 11 项频道操作，以及文件、完整说明、进度卡、提问和表单。每条输入、卡片答案、工具及交付重新核验当前人类、好友关系和官方单条私聊消息访问权；不能仅凭好友检查绕过应用空间限制。群聊、子区、空间搜索、授权搜索、跨会话发送、语音服务和原生命令菜单不作为 App 能力显示。插件自身的斜杠命令仍可用；User Bot 的 52 项频道操作保持。

正式 App Bot 注册、客户端卡片显示与真实消息验收仍单独跟踪；合成接口和真实 DSH 宿主测试不等于正式 Octo 客户端验收。

## 0.16.0

新增联系人名称查询 `messages.resolve_people`，并将既有指定目标发送扩展到第三方私聊；频道操作共 52 项。用户可在获准使用工具的私聊中，明确要求 Bot 向同一空间内的联系人发送文字、工作区文件/图片附完整说明或展示卡。查询支持分页及重名候选，目录结果不代表好友关系；实际投递由 Octo 再检查 Bot 与收件人的好友权限，不读取收件人的聊天记录作为发送预检，不使用用户代发。

既有群聊和子区发送保持不变。另修复发送请求已经获得有效回执、但同时取消任务或更改设置时丢失回执的问题：保留已确认的消息编号，停止余下交付，不把已送达内容当成失败重发。正式客户端复验及 App Bot 等未完成项目继续见[能力矩阵](OCTO-COVERAGE.md)。

## 0.15.0

修复任务完成后仍按旧权限投递的问题。最终文字、文件、图文和展示卡在发送前重新核对当前账号和频道准入；文件在申请上传、上传字节与发布消息之间分别检查。任务期间更改工作区、工具权限或停用账号，会停止剩余交付，保留已确认回执，不自动重发。已生成的回复记录不含凭据的配置摘要，重启恢复时也会核对；修改账号名称或发送方式不会丢弃正常回复。

当前 51 个频道操作保持不变。原生问答、审批、表单、群成员与规则、授权检索、指定群/子区文字、文件和展示卡均继续回归；正式 Octo 客户端显示与未完成能力单独记录在[能力矩阵](OCTO-COVERAGE.md)。

发布前 1006 项自动测试全部通过、无跳过，其中 65 项覆盖交付期间配置变化、部分回执、进度卡与恢复。最终源码在 Windows 和 Debian 同版本隔离 DSH Web 中均通过完整联调，使用合成 Octo/模型，不替代正式客户端验收。

## 0.14.0

新增 `messages.send_target_file` 和 `messages.send_target_card`，频道操作共 51 项。在获准使用 DSH 工具的私聊中，可按用户明确要求向指定群或子区交付工作区文件、图片或结构化展示卡。文件仅接受当前工作区相对路径，仍核对附件开关、权限与文件边界；名称目标须先解析，有歧义时请用户选择。发送前后不改变会话归属。

文件说明作为完整文字/Markdown独立发送。文件成功而说明未确认时，返回文件回执和部分投递状态，不重发整个文件；图片使用原生图片消息。展示卡按服务端能力配置保留内容并降级不支持的元素，不包含回调按钮。获取上传地址、上传字节和发布消息分别核对当前权限。修复官方旧版 HTTP 400 包装内部发送失败的判断，展示卡和图文不再把未知投递当成确定拒绝后重复发送。

0.14.0 发布前 941 项完整回归通过、无跳过；Windows 和 Debian 同版本隔离 DSH 均验证指定群文件、完整说明、子区展示卡及原生回执/最终回复，并回归既有群工具、审批、问答和表单。正式 Octo 多客户端渲染、真实授权检索及其他未完成能力仍见能力矩阵。

账号管理参照 IM Connect 1.0.30。两个插件可共存，各自保留账号、会话与凭据。默认的文字模式可复用已经在 DSH Web 打开的空闲 Octo 会话。同回合混入其他来源的输入时不会向 Octo 转发。

- **设置 → Octo 渠道 → Bot 账号**：渠道卡片显示账号数量、连接状态和「接收消息」开关；添加与设置使用同一个双栏表单。每个账号独立选择 DSH 已登记的工作区、Agent 预设、模型、推理强度、权限、私聊准入和空闲新会话时间。已有服务器账号自动出现在列表中，沿用原有历史。
- **添加、验证和更换令牌**：在已登录的 DSH Web 页面可用，HTTP 和 HTTPS 均可。服务端固定 Octo API 地址；新令牌仅保存到 DSH 凭据库，不回显。移除接入保留 DSH 会话与历史。
- **权限与工具范围**：默认保留原有权限。「工具使用范围」独立选择 `private`（获准私聊）、`owner`（Bot 所有者全部已准入会话）或 `admitted`（所有已准入用户）。范围内使用所选 Agent 预设已挂载的 DSH 工具、插件与技能，包含群聊和子区；实际操作仍受权限策略约束。预设可选项由部署配置 `hostPermissions` 决定。普通群友可使用当前频道的 Octo 工具，不能因此访问工作区。「仅文字」不开放任何工具，「只读」不挂载 Octo 写操作；宿主审批仍由 DSH 处理。
- **发送方式**：默认排队。启用「插话发送」后，同一频道、同一获准使用 DSH 工具的用户可在 WebSocket 下补充文字。附件准备期间，补充要求与附件一起交给模型；模型已开始时，DSH 在可插话的下一步接收补充。插话不是立即终止已运行的工具，其他来源的消息继续排队。
- **渠道设置**：选择账号后独立配置群聊/子区名单、@ 触发、子区规则、进度和超时。普通配置保存后对新消息立即生效，不中断当前任务；修改工作区、模型或权限会在需要时开新 DSH 会话，旧会话仍可查看。
- **侧栏 → Octo**：有宿主扩展页签时，显示一个 Octo 页签；没有时，在侧栏底部提供「Octo 频道」入口。私聊、群聊和子区自动归档；可按类型筛选、搜索并打开原生 DSH 会话。原生 Octo 页签的「…」和右键打开同一组宿主会话操作。
- **删除会话后继续聊天**：频道列表以 DSH 原生会话是否存在为准，正常刷新会移除已删除项。下一条 Octo 消息自动创建新会话，不再尝试恢复已删除的会话；原消息的去重和投递回执保留。宿主读取失败、格式损坏或会话忙不会当成删除。
- **进度**：长回复优先使用 Octo 推理过程模板，或使用展示卡；卡片不可用时回退到“正在输入”。卡片显示 DSH 的真实步骤、工具执行结果、文件交付数量和耗时，不包含模型原始推理或工具参数。进度失败不阻止正文；明确失败有提示，旧任务不会自动重放。
- **提问与回答**：多题按顺序展示；提交后原卡显示收到的答案并关闭按钮，随后显示下一题。答题期间暂停模型执行计时，整组问题最多等待 15 分钟。服务重启会结束原等待，旧卡改为结束提示，需重新发起提问；不会把旧卡答案误当作新指令执行。
- **表单**：`octo_form` 可在原回合等待文字、数字、日期、时间、开关、单选/多选结果，最多 8 个字段、6 个提交按钮；原生提问也支持文字和多选卡。客户端不支持输入控件时提供文字填写格式；无效文字答案会提示检查，投递不明时不重复发卡。提交只代表回答，不代替工具审批。
- **命令菜单**：账号设置中可明确发布 `/help /status /new /card /choose` 或清空菜单。操作会替换此 Bot 的整个菜单，页面先显示确认；启动、保存普通设置和移除账号均不自动改 Octo 菜单。
- **文件与说明**：启用账号的文件选项后，已通过准入的私聊、群聊和子区可以接收文件、图片、GIF、语音和视频附件。图片是否可识别取决于所选模型。当前语音附件可通过 `octo_voice_transcribe` 调用 Octo 转写服务，服务未开放或超限会返回明确错误；不接受任意本地路径、其他消息或外部音频网址。发送须符合工具范围和权限，仅交付本轮通过 DSH 正式声明的工作区文件。文件独立发送，完整最终正文另发；带 Markdown 的图片说明也保留为文字消息。默认每个文件上限 16 MiB，语音服务可有更低限制；部署需配置确切的 `mediaDownloadOrigins`、`mediaUploadOrigins` HTTPS 来源。投递无法确认时不自动重发。
- **群聊前文、成员与引用**：触发后补充当前群或子区的近期可读消息及真实成员名称；不把群历史放进私聊。明确要求提及时，最终正文中的 `@[uid:姓名]` 核对当前成员后转为原生 @；代码和引用中的例子不触发通知。私聊普通回复不附加空引用，群回复仅在有消息序号、作者和摘要时附加完整引用。长正文按 Markdown 块分段，保留代码、链接和表格。详见[消息兼容矩阵](OCTO-COVERAGE.md)。
- **Octo 频道工具**：可查询当前群成员、近期消息与搜索结果，读取或更新规则，管理子区、发送当前频道通知及编辑 Bot 自己的文字。管理动作每次核对请求者与 Bot 的实时权限。受限会话只挂载 Octo 工具，获准的会话保留 DSH 工具。普通私聊查询仅限本会话；另有下面三种独立授权检索，完整清单及官方接口缺口见能力矩阵。
- **授权跨频道检索**：获准使用 DSH 工具的用户可在私聊请求检索明确指定的 1–5 个群/子区的消息、文件或群摘要。需要 Octo 已有的旧式全局 OBO 授权；仅与 Bot 好友、同群或拥有 DSH 权限均不足以授权跨频道读取。当前官方授权创建入口通常限 Bot 创建者，新式策略授权不能代替此搜索授权。返回授权接口给出的有限摘要与文件元数据，不额外取全文、下载链接或附件。续页标识绑定账号、发起人、查询和目标，5 分钟过期，重配后失效；不提供无目标的全局发现。
- **指定联系人／群／子区发送**：在获准使用工具的私聊中明确说“把这段通知发给某人／某群／子区”，可先按名称查找目标，再以 Bot 身份发送文字、Markdown、工作区文件、图片及展示卡。联系人须为固定空间内的有效人类，实际发送检查 Bot 好友权限；群和子区须符合频道名单及你与 Bot 的当前成员身份，可使用原生 @，@所有人需群管理权限。重名或结果不完整时需确认具体目标。不会冒充你发言，不附加空引用；结果不明不自动重发。
- **编辑已发内容**：可修改当前会话中 Bot 自己发送的文字、图文消息和普通展示卡；不能用编辑工具改写进度卡、提问卡或带回调的卡片。读取原消息与实际编辑内容后重新核验身份和权限，写入未确认时不自动重试。
- **卡片与安全命令**：在账号的私聊或群聊命令选项开启后，授权操作者可使用 `/help`、`/status`、`/new`、`/card` 和 `/choose`。群聊和子区还要求 Bot 所有者直接 @ Bot。卡片按钮只接受原账号、原会话与指定用户的有效回调。授权用户可直接要求展示卡片；不支持的卡片退回文字。长正文会分段发送。
- **权限审批**：本轮 DSH 工具发起的审批可在 Octo 中回答。展示已提交的真实工具参数，仅批准一次；拒绝、取消、超时、信息缺失或未完整展示均不执行。审批绑定原发起人、原频道和原生回合，参数含敏感内容时不在 IM 中批准；不改变宿主权限策略，不代替插件安装等其他审批流程。
- **离线恢复**：从此版本实际收到过的频道建立恢复起点，重连和定时检查按历史顺序补收、去重。恢复失败时暂存新消息并在账号页提示；撤回内容不从暂存区执行。升级前的旧聊天、新频道尚未收到的第一条消息和服务端已丢失的历史不在恢复保证内。
- **身份与集成诊断**：增加当前会话成员的单个/批量身份查询，以及当前群/子区的 Webhook 列表和投递记录。查询不增加跨群权限，不返回 Webhook 密钥或推送地址，不执行测试推送。
- **Webhook 管理**：账号设置中打开「管理 Webhook」，选择当前 Bot 所在空间的群或子区，可创建、修改、启停、删除、轮换密钥、查看投递记录，并明确确认后发送测试消息。一次性令牌和适配器地址仅在当前已登录管理界面显示，默认遮盖，关闭或切换频道后清除；不会保存到模型、聊天记录或账号概览。HTTP 局域网入口也可使用，仍须登录与同源校验。模型工具另支持当前群/子区的修改、删除和明确请求的测试发送，实时核对请求者和 Bot 的管理权限。
- **卡片历史清理**：Bot 所有者可明确要求清除当前会话中 Bot 自己展示卡的修订历史；群内还要求群管理权限。保留当前卡片与服务端审计记录；不清理提问、审批、进度或 Registry 卡片，不会取消正在等待的交互。
- **明确失败原因**：按官方错误码区分权限不足、功能关闭、服务不可用和搜索边界，兼容部分接口 HTTP 400 内携带其他错误状态的情况。不暴露服务端原始错误、令牌或链接。会话忙、模型缺失、超时和附件失败分别给出中文提示；结果不明时先核对执行状态，不自动重放或要求直接重发。
- **范围**：User Bot（`bf_`）支持私聊、群聊及子区；App Bot（`app_`）为独立的当前私聊模式。没有任意 Adaptive Card 结构、原生逐字流、不受准入约束的跨频道发送或 Octo Drive/Docs。详见[双方源码对照与验收边界](IM-CONNECT-PARITY.md)。

自动测试覆盖权限校验、断线重连、收件确认和重复消息去重。隔离 DSH Web 与 IM Connect 共同加载，用模拟 Octo 和模型检查规则、会话隔离和进度卡更新。可另传 Playwright 模块与 Chromium 路径，验证浏览器设置页。
